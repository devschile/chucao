# Backlog

This file tracks the increments of the project. **GitHub issues are the source
of truth for work that is still open** — this file is the map, the issues are
where the work happens.

- Every open item below links to its issue.
- Items marked **discussion** are ideas that still need a decision. Don't start
  writing code for them; comment on the issue instead.
- **Taking an item that has no issue link?** Open the issue first, then add the
  link here in the same pull request.
- **Working on something that isn't listed here at all?** If it shapes a release
  — a new component, a breaking change, a new increment — open an issue and add
  it to this file, so it's visible to everyone before the code exists. Smaller
  changes like a typo or a bug in an existing component just need an issue, not a
  backlog entry.

See [`CONTRIBUTING.md`](../CONTRIBUTING.md) for the full contribution flow.

### CH-03.1 — Validation states on form controls

- **CH-03.1** Added `hint`, `errorMessage`, and `invalid` props to `ch-input`
  and `ch-select`. `hint` renders helper text and is wired via
  `aria-describedby`; when `invalid` + `errorMessage` are set, the hint is
  replaced by the error message (`role="alert"`) and the control gets
  `aria-invalid="true"` plus red border/focus-ring styling via the
  `--color-status-warning*` tokens. Error/hint styles use only design tokens
  (`--typography-size-sm`, `--spacing-sm`, `--color-status-warning*`).
- **CH-03.1** Specs: 8 new tests (4 per component) covering hint/error
  rendering, `aria-describedby`/`aria-invalid` wiring, error-vs-hint
  precedence, and the valid-state omission of error markup. Verified:
  `pnpm lint` (no warnings), `pnpm test` (29/29), `pnpm run build` all green;
  `src/components.d.ts` and both `readme.md` regenerated by the build.

### CH-03.2/03.3 — New form controls

- **CH-03.2** New components, each with `.tsx` + `.css` + `.plugin.spec.tsx` +
  auto-generated `readme.md`:
  - `ch-checkbox` — native `<input type="checkbox">` with implicit-label
    association, `checked` (mutable), `chChange` event, plus the CH-03.1
    `hint`/`errorMessage`/`invalid` validation props.
  - `ch-radio` — radio group driven by a `ChRadioOption[]` `options` prop and
    a selected `value` (mirrors `ch-select`); renders `role="radiogroup"`
    labelled via `aria-labelledby`, auto-generates a shared `name` when none
    is given, emits `chChange` with the selected value.
  - `ch-switch` — native `<input type="checkbox" role="switch">` with a
    track/thumb, `checked` (mutable) reflected in `aria-checked`, `chChange`
    event, and the same validation props.
  - `ch-textarea` — native `<textarea>` with `label`/`rows`/`placeholder`,
    `chInput`/`chChange` events, and the same validation props.
  - All styles are token-driven (`--spacing*`, `--radius*`, `--border-width`,
    `--accent`, `--color-status-warning*`, focus ring/outline tokens) — no
    hardcoded colors/sizes. Invalid state reuses the red
    `--color-status-warning*` treatment from CH-03.1.
- **CH-03.2** Gallery: added demo entries for the four components in
  `scripts/gallery-data.mjs` (alphabetical order) and regenerated
  `docs-site/index.html` + `docs-site/assets/js/app.js` via

### CH-05 — Navigation & content

- **CH-05.1** New components, each with `.tsx` + `.css` + `.plugin.spec.tsx` +
  auto-generated `readme.md`:
  - `ch-link` — native `<a>` with `default`/`muted` variants; auto-adds
    `rel="noopener noreferrer"` for `target="_blank"`; when `disabled` renders
    a non-interactive element with `aria-disabled="true"`. Emits `chClick`.
  - `ch-divider` — native `<hr>` with `horizontal` (default) / `vertical`
    orientations and `aria-orientation`.
  - `ch-tabs` — WAI-ARIA tablist driven by a `ChTab[]` `tabs` prop and a
    selected `value`; arrow-key navigation (Left/Right wrap, Home/End to
    first/last, disabled tabs skipped) with a roving `tabindex`, `aria-selected`
    wiring, and `role="tabpanel"` panels whose consumer content is distributed
    via named `panel-<value>` slots (only the active one visible). Emits
    `chChange` with the selected value.
  - `ch-accordion` — WAI-ARIA accordion with single-open semantics driven by
    `ChAccordionItem[]` `items` and an open `value`; a native `<button>` per
    item with `aria-expanded`/`aria-controls` and `role="region"` panels via
    named `panel-<value>` slots. Emits `chChange` with the new open value
    (`undefined` when all items are closed).
  - All styles are token-driven (`--spacing*`, `--radius*`, `--border-width`,
    `--border-accent-bar`, `--accent*`, `--text*`, focus ring/outline tokens) —
    no hardcoded colors/sizes.
- **CH-05.2** Gallery: added demo entries for the four components in
  `scripts/gallery-data.mjs` (alphabetical order) and regenerated
  `docs-site/index.html` + `docs-site/assets/js/app.js` via
  `pnpm run generate:gallery` (13 component blocks). Documented the new
  `ch-tabs` arrow-key navigation and slotted-panel conventions in
  `docs/components.md`.
- **CH-05.2** Verified: 35 new tests (91 total), full suite green; coverage
  **100%** statements/functions/lines (94.88% branches); `pnpm lint` (no
  warnings) and `pnpm run build` green; new files Prettier-clean.
